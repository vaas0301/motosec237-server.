# BASE DE DONNÉES — MOTOSEC 237 v0.1

Fichier de référence : `db/schema.sql` (appliqué par le serveur au
démarrage, et par les tests). 13 tables du prompt maître, plus 4 tables
techniques (`devices`, `operations`, `otp_codes`, `audit`).

## Tables

| Table | Rôle | Clés |
|---|---|---|
| `app_users` | Clients, conducteurs, admins, sécurité | PK `id` (TEXT/UUID), `phone` UNIQUE, `role`, `language` fr/en |
| `emergency_contacts` | Proches à prévenir | FK `user_id` → `app_users` |
| `drivers` | Conducteurs, statut de vérification | FK `user_id` UNIQUE, `status` pending/verified/suspended/rejected, `online` 0/1, `rejection_reason`, `last_lat/lng/seen_at` (v0.3) |
| `motorcycles` | Motos identifiées par plaque | FK `driver_id`, `plate` UNIQUE, `box_code` UNIQUE (nullable, v0.3) |
| `rides` | Courses (brouillon → terminée) | FK client/driver/moto, `op_id` UNIQUE, `status` |
| `parcels` | Colis, code de traçabilité unique | FK `ride_id`, `tracking_code` UNIQUE |
| `gps_points` | Historique des positions (1 ligne / point) | FK `ride_id`, index `(ride_id, recorded_at)` |
| `ride_events` | Journal des événements d'une course | FK `ride_id`, `op_id` UNIQUE |
| `incidents` | SOS, déviations, immobilisations | FK `ride_id`, `status` open/qualified/resolved/closed |
| `payment_transactions` | Transactions, références, commissions | FK `ride_id`, `reference` UNIQUE |
| `tracking_devices` | Balises GPS autonomes (complément téléphone) | FK `motorcycle_id`, `device_code` UNIQUE |
| `notifications` | Notifications in-app | FK `user_id` |
| `ratings` | Notations 1–5 après course | FK `ride_id`, `driver_id` |
| `devices` | Appareils enregistrés (jeton) | `token` UNIQUE, `revoked` |
| `operations` | Journal des `op_id` (idempotence) | PK `op_id`, `payload_hash` |
| `otp_codes` | Codes OTP hachés | PK `phone`, `attempts`, `expires_at` |
| `audit` | Journal des opérations sensibles | — |

## Règles d'intégrité

- `PRAGMA foreign_keys = ON` (SQLite) ; les suppressions en cascade ne
  concernent que les données liées à un utilisateur (`ON DELETE CASCADE`).
- Une course ne peut pas exister sans client ; une moto sans conducteur
  vérifié ne peut pas être attribuée (contrôle applicatif, phase 4).
- `gps_points.lat/lng` bornés (-90/90, -180/180) par `CHECK`.
- `ratings.stars` entre 1 et 5 par `CHECK`.

## Portabilité PostgreSQL

Types choisis pour être portables : `TEXT`, `INTEGER`, `REAL`, `BOOLEAN`
(`INTEGER 0/1` sous SQLite), horodatages ISO 8601 en `TEXT`, UUID en `TEXT`.
Adaptations à la bascule (documentées aussi dans `ARCHITECTURE.md` § 4) :
`INTEGER PRIMARY KEY AUTOINCREMENT` → `INTEGER GENERATED BY DEFAULT AS
IDENTITY`, `BOOLEAN` natif, ajout PostGIS (`geography(Point, 4326)`,
index `GIST`) pour `gps_points` et la dernière position des conducteurs.

## Données de démonstration

La v0.1 ne contient **aucune donnée de démonstration** en base. Les tests
créent leurs propres données temporaires (base `/tmp/motosec237_test.db`,
détruite à chaque lancement). Aucun conducteur, aucune course, aucun
tarif n'est présenté comme réel.
