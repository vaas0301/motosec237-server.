# ARCHITECTURE — MOTOSEC 237 v0.1 (base épurée)

## 1. Vue d'ensemble

```
Téléphone Android (Flutter, FR/EN, Google Maps)
        │  HTTPS, JSON, une seule BASE_URL configurable
        ▼
Serveur EN LIGNE (FastAPI + SQLite en dev)
        │  SQL portable
        ▼
Base de données (SQLite en dev, PostgreSQL en production — bascule doc.)
```

## 2. Choix retenus pour la v0.1 (et pourquoi)

### 2.1 Flutter + Riverpod + Clean Architecture

L'appli est en Flutter (un seul code Android, iOS possible plus tard),
Riverpod pour l'état (langue, connexion), architecture en couches
(`lib/` : config, theme, geo, services, screens, data). C'est le socle
éprouvé de MinePilot v3, adapté à MOTOSEC 237 — sans copier son métier
minier.

### 2.2 Serveur EN LIGNE UNIQUEMENT (décision utilisateur, 2026-11-10)

L'utilisateur a décidé : **« Je veux un serveur en ligne. Ici le local
n'est pas utile à mon avis. »** Il n'y a donc **pas de serveur local
Wi-Fi** dans MOTOSEC 237 (pas de port 8767, pas de `Lancer-Serveur.bat`,
pas d'adresse IP locale en dur). Le serveur est accessible par internet,
depuis n'importe où. C'est cohérent avec Google Maps, qui exige internet
de toute façon.

La synchronisation offline-first **reste utile dans l'appli** : quand le
réseau de Meiganga coupe, les opérations sont mises en file d'attente
(`op_id`, accusé, idempotence) et renvoyées quand le réseau revient.
La file protège contre les coupures, elle ne remplace pas un serveur local.

### 2.3 FastAPI + SQLite en dev (et pas NestJS / PostgreSQL maintenant)

Le prompt maître proposait NestJS + PostgreSQL/PostGIS + React admin.
Pour la **base v0.1**, ce choix est volontairement reporté. Comparaison :

| Critère | FastAPI + SQLite (v0.1) | NestJS + PostgreSQL/PostGIS |
|---|---|---|
| Coût de démarrage | 0 FCFA (hébergement gratuit possible, voir déploiement) | 0 FCFA aussi, mais plus de pièces à opérer |
| Mise en route | Un seul fichier `main.py`, une seule base fichier | Migrations, ORM, PostGIS à installer |
| Équipe / outillage | Patron déjà éprouvé ici (MinePilot v3) | Nouveau socle à stabiliser d'abord |
| Hors ligne (appli) | File `op_id` identique dans les deux cas | Idem |
| Requêtes spatiales | Haversine en code (suffisant à Meiganga, trajets de quelques km) | PostGIS (index spatiaux, `ST_DWithin`) |
| Montée en charge | Suffisant pour le pilote (quelques dizaines de conducteurs) | Nécessaire au-delà de la zone pilote |

**Décision :** on garde FastAPI pour la v0.1, on **ne construit pas**
NestJS/PostGIS maintenant, on documente le chemin de migration
(voir § 4). Refaire un socle NestJS avant d'avoir validé le pilote
serait du travail jeté si le modèle métier change après les premiers
tests à Meiganga.

### 2.4 Google Maps (décision utilisateur, 2026-11-10)

L'appli doit être liée à **Google Maps** (pas OpenStreetMap en
principal). Carte centrée sur Meiganga, marqueurs, suivi GPS.
Contraintes honnêtes : internet obligatoire + clé API avec facturation
activée. Sans réseau : mode dégradé (dernière position + liste, sans
carte). Voir `docs/GOOGLE-MAPS.md`.

### 2.5 Bilingue FR / EN (décision utilisateur, 2026-11-10)

Français par défaut, anglais disponible. Choix au premier lancement +
dans Profil > Langue, persisté localement. Chaînes centralisées
(`lib/l10n/app_strings.dart`), test d'exhaustivité FR/EN.

### 2.6 Design combiné vert émeraude + bleu ciel (décision utilisateur)

Vert émeraude = marque (logo, boutons principaux, succès). Bleu ciel =
deuxième couleur (fonds de carte, suivi, boutons secondaires, états
« en cours »). Voir `docs/DESIGN-SYSTEM.md`.

## 4. Chemin de migration vers PostgreSQL / PostGIS (plus tard)

1. Remplacer `DATABASE_URL` par `postgresql://...` (variable d'env).
2. Appliquer `db/schema.sql` adapté : `BOOLEAN` natif, `INTEGER
   GENERATED BY DEFAULT AS IDENTITY` pour `gps_points.id`,
   `ride_events.id`, `audit.id` ; `TEXT` inchangé.
3. Activer PostGIS et ajouter une colonne `geom geography(Point, 4326)`
   sur `gps_points` et `drivers` (dernière position), index `GIST`.
4. Remplacer la recherche Haversine par `ST_DWithin` dans
   `GET /drivers/nearby`.
5. Migrer les données SQLite → PostgreSQL (`pgloader` ou export SQL).
6. Déployer avec une base managée chez l'hébergeur (voir déploiement).

Aucune de ces étapes n'est construite dans la v0.1.

## 5. Internationalisation (FR / EN)

- `lib/l10n/app_strings.dart` : toutes les chaînes, FR et EN.
- `flutter_localizations` dans `pubspec.yaml` (dates, nombres).
- Test `test/strings_test.dart` : les deux langues ont exactement les
  mêmes clés — une chaîne ajoutée en français sans sa traduction anglaise
  fait échouer les tests.
- Ajouter une langue : ajouter une entrée dans `appStrings`, ajouter le
  `Locale` dans `main.dart`, relancer les tests.

## 6. Sécurité (v0.1)

- Aucun secret dans le code (variables d'environnement, `.env.example`).
- Jeton par appareil, révocable (`devices.revoked`).
- OTP : 6 chiffres, 10 min, 5 tentatives max, haché SHA-256 en base.
- Journal d'audit (`audit`) pour les opérations sensibles.
- CORS restrictif (origines listées par variable d'environnement).
- HTTPS en production (terminaison TLS chez l'hébergeur, voir déploiement).

Limites connues de la v0.1 (à traiter dans les phases suivantes) :
chiffrement au repos non activé, pas de limitation de débit (rate
limiting) sur `/auth/otp/request`, OTP SMS via agrégateur non branché,
pas de chiffrement des documents d'identité des conducteurs.
